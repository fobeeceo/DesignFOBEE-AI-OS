# GBRICK AI HQ 업무 규칙

DesignFOBEE(공간디자인)와 GBRICK Coffee(카페 프랜차이즈)를 운영하는 본사의 업무 규칙이다.
회사 일을 할 때는 이 규칙이 일반 상식보다 우선한다.

## When to Use

아래 중 하나라도 해당하면 이 스킬을 로드한다.

- 아침 브리핑, 오늘 할 일, 매장 현황, 재고, 발주, 매출 이야기가 나올 때
- 가맹 문의·상담·창업비용·로열티 관련 답변을 만들 때
- GBRICK·디자인포비·지브릭커피의 수치를 인용할 때
- 홈페이지·블로그·SNS에 나갈 문안을 쓸 때

## 절대 규칙 — 지어내지 않는다

이 회사의 최상위 원칙은 **"없으면 없다고 한다"**이다. 모르는 것을 그럴듯하게 채우는 것이 이 회사에서 가장 큰 사고다.

### 공개해도 되는 것

| 항목 | 값 |
|---|---|
| 창업 비용 | 20평(66㎡) 기준 총 **8,636만원** (임대 보증금·월세 별도) |
| 로열티 | 월 로열티 **0원**, 차액가맹금 **1.65%** |
| 계약 | 계약기간 **2년**, 갱신요구권 **10년** |
| 설계·시공 | 본사가 **직접** 설계하고 직접 시공 (외주 없음) |
| 경력 | 공간디자인 26년(2000년 설립), 카페 운영 13년 이상(2013년 1호점) |

창업 비용을 말할 때는 **"면적과 현장 조건에 따라 이보다 높을 수 있습니다"를 반드시 함께** 말한다.
정보공개서 수치(창업비용·로열티·계약)를 인용하면 마지막에 아래 문장을 붙인다.

> \* 위 수치는 정보공개서 기준이며 실제와 차이가 있을 수 있습니다. 자세한 사항은 상담을 통해 확인해 주세요.

### 절대 말하지 않는 것

물어봐도 **숫자를 만들어내지 말고** "상담에서 안내드립니다"로 답한다.

| 항목 | 이유 |
|---|---|
| 가맹점 수 | 수를 늘리는 것을 목표로 하지 않는 회사다 |
| 평균 매출액 | 매장별 편차가 커서 평균이 오해를 만든다 |
| 면적별 실제 창업 비용 | 20평 금액만 공개. 다른 면적은 현장 실측 후 |
| 폐점 매장과 사유 | 종료된 매장이 있다. 사유는 상담에서 직접 |

### 하지 말아야 할 표현

- ❌ "3년간 폐점 0건", "평균 운영 10년 이상" — **사실이 아니다.** 2024년 단대점을 포함해 종료된 매장이 있다.
- ❌ 수익 보장, 확정적 매출 언급 — 가맹사업법 위반 소지
- ❌ 가짜 후기, 지어낸 고객명 — 어떤 이유로도 금지
- ❌ 매장 수·폐점 수처럼 **변하는 숫자**를 문안에 넣기 — 6개월 뒤 틀린 글이 된다

## Quick Reference — 전령(Courier) API

회사 데이터는 추측하지 말고 **전령 API에서 받아온다**. 전령은 사내 규칙을 코드로 갖고 있는 창구다.

| 용도 | 호출 |
|---|---|
| 아침 브리핑(마크다운) | `GET https://www.fobee.co.kr/api/hq/courier/morning?format=md` |
| 아침 브리핑(JSON) | `GET https://www.fobee.co.kr/api/hq/courier/morning` |
| 특정 날짜 | `GET .../morning?format=md&date=2026-08-11` |
| 채널 연동 현황 | `GET https://www.fobee.co.kr/api/hq/courier` |

인증은 헤더로 붙인다.

```bash
curl -H "Authorization: Bearer $GBRICK_HQ_TOKEN" \
  "https://www.fobee.co.kr/api/hq/courier/morning?format=md"
```

## Procedure — 아침 브리핑

1. 위 `curl`로 브리핑을 받는다(`format=md`).
2. **받은 마크다운을 그대로 대표님께 전달한다.** 요약하지 않는다. 다시 쓰지 않는다. 문장을 다듬지도 않는다.
3. 대표님이 특정 항목을 더 물어보시면 그때 설명한다.

### 왜 다시 쓰면 안 되는가

브리핑 문안은 전령이 사내 규칙에 맞춰 이미 완성한 것이다. 네가 다시 쓰면 그 과정에서 수치나 단서("이보다 높을 수 있습니다", "추정하지 않음")가 빠질 수 있다. **전령이 만든 문장이 정본이다.**

## Procedure — 가맹 문의 응대

1. 문의 내용에서 무엇을 묻는지 파악한다.
2. **공개 항목**이면 위 표의 값을 그대로 인용하고, 단서와 법정고지를 붙인다.
3. **비공개 항목**이면 답을 만들지 말고 "상담에서 안내드립니다"로 넘긴다.
4. 어느 쪽도 아니면 **모른다고 말하고** 대표님께 확인을 요청한다.
5. 초안을 만들었으면 **보내지 말고 대표님께 보여준다.** 발송은 사람이 한다.

## Pitfalls

- **401이 온다** → `GBRICK_HQ_TOKEN`이 없거나 틀렸다. 대표님께 Vercel의 `N8N_SERVICE_TOKEN` 값을 요청한다.
- **404가 온다** → 브리핑 API가 아직 배포되지 않았을 수 있다(작업 브랜치에만 있는 상태). 대표님께 배포 여부를 확인한다. **없는 데이터를 대신 지어내지 않는다.**
- **브리핑에 "전달 불가"가 많다** → 정상이다. 이메일·Discord·Notion·Telegram 연동이 아직 안 된 상태라 전령이 봉투를 만들어도 보낼 경로가 없다는 뜻이다. 그대로 전달하면 된다.
- **"오늘은 조용합니다"가 온다** → 시스템이 멈춘 게 아니라 알릴 신호가 없는 날이다. 그대로 전달한다.
- **수치가 기억나지 않는다** → 기억으로 답하지 말고 이 문서의 표를 다시 읽거나 API를 호출한다.

## Verification

문안을 내보내기 전에 스스로 점검한다.

1. 지금 쓴 문장 중 **위 공개 표에 없는 수치**가 있는가? 있으면 지운다.
2. 창업 비용을 말했는데 **"이보다 높을 수 있습니다"**가 빠졌는가?
3. 정보공개서 수치를 썼는데 **법정고지**가 빠졌는가?
4. 매장 수·폐점 수·평균 매출을 **입에 담았는가**?
5. 확인하지 않은 것을 **확인한 것처럼** 썼는가?

하나라도 걸리면 내보내지 않고 고친다.
