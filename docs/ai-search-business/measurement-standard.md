# AI 검색 노출 진단 — 측정 기준서
버전: 1.0 · 작성일: 2026-10-24

> 이 문서는 모든 측정 결과 계산·해석의 기준이다.
> 보고서에 숫자를 넣기 전에 이 기준을 따랐는지 확인한다.

---

## 1. 언급 상태 4종 정의

| 상태 | 코드 | 정의 | 집계 처리 |
|---|---|---|---|
| 언급됨 | `MENTIONED` | AI 응답에 해당 브랜드/매장이 명시적으로 포함됨 | 분자 + 분모 |
| 미언급 | `NOT_MENTIONED` | AI가 응답했지만 해당 브랜드를 언급하지 않음 | 분모만 |
| 측정 실패 | `FAILED` | API 오류·타임아웃 등으로 결과를 얻지 못함 | **분모에서 제외** |
| 미측정 | `UNMEASURED` | 아직 측정하지 않은 질문 | **집계에서 제외** |

**핵심 불변 원칙**: `FAILED ≠ NOT_MENTIONED`. 실패한 질문은 미언급으로 처리하지 않는다.

## 2. 노출률 계산 공식

### 기본 공식
```
성공 분모 = 전체 질문 수 - FAILED 수 - UNMEASURED 수
노출률(성공 기준) = MENTIONED 수 / 성공 분모 × 100
```

### 예시 (GBRICK Coffee 2026-10-24 측정)
```
전체 질문: 20
MENTIONED: 6
NOT_MENTIONED: 13
FAILED: 1 (Q03)
UNMEASURED: 0

성공 분모 = 20 - 1 - 0 = 19
노출률(성공 기준) = 6 / 19 = 31.6%
```

### 주의 사항
- "전체 기준 노출률"(FAILED 포함)은 **부가 참고값**이다. 주요 지표는 성공 기준이다.
- FAILED 문항이 많을수록 결과 신뢰도가 낮아진다. FAILED 수를 반드시 명시한다.

## 3. 일반 검색 vs 브랜드 직접 검색 구분

| 카테고리 | 정의 | 비고 |
|---|---|---|
| **일반 검색** | 질문에 브랜드명·상호명이 포함되지 않는다 | "은평뉴타운 카페 추천" |
| **브랜드 직접 검색** | 질문에 브랜드명·상호명이 포함된다 | "GBRICK Coffee는 어떤 카페야?" |

두 카테고리는 **별도로 집계한다**. 혼합하면 전체 노출률이 브랜드 직접 검색에 의해 과장된다.

### 이유
브랜드명을 직접 물어보면 AI가 알고 있는 정보를 출력한다 → 이것은 "노출"이 아니라 "정보 조회"다.
고객이 실제로 유입되는 경로는 **일반 검색** (브랜드를 모르는 상태에서 질문)이다.

## 4. 반복 측정 및 비교 원칙

### 동일 조건 유지
반복 측정 시 다음을 동일하게 유지한다:
- 질문 텍스트 (코드 Q01~Q20 기준 — 수정 시 버전 업)
- AI 서비스 (GEMINI / CHATGPT)
- AI 모델 버전 (명시 필수)
- 타임아웃 설정 (30초)

### 비교 시 주의
- 모델이 다르면 직접 비교하지 않는다 (모델 변경은 외부 요인)
- 직전 측정 대비 변화를 기본 비교 단위로 한다
- 장기 추이(6개월+)는 같은 모델 기간 내에서만 비교한다

### 재측정 규칙
- `FAILED` 문항은 재측정 대상이다 (타임아웃은 일시적일 수 있다)
- 재측정 결과로 원본을 대체하되, **원본 결과도 보존**한다
- 재측정에서도 `FAILED`이면 결측 처리 — 추정으로 채우지 않는다

## 5. 출처 기록 규칙

| 항목 | 기록 방법 |
|---|---|
| 출처 URL | AI 응답의 grounding URL 최대 3개 저장 |
| 증거 텍스트 | MENTIONED일 때 언급된 텍스트 스니펫 저장 (최대 200자) |
| 실패 사유 | FAILED일 때 오류 메시지 저장 (API 키 등 민감정보 제거 후) |

### 확인 불가 시 처리
- grounding URL이 없거나 출처를 확인할 수 없으면 "출처 없음"으로 기록한다.
- 출처가 없어도 MENTIONED 판정은 가능 (AI 응답 텍스트가 증거)

## 6. 모델과 측정 시점 기록 (필수)

모든 측정 결과에 다음을 기록한다:

| 항목 | 예시 |
|---|---|
| AI 서비스 | `GEMINI` |
| 모델 ID | `gemini-3.8-flash` |
| 측정 일시 | `2026-10-24T14:30:00+09:00` |
| 타임아웃 설정 | `30000ms` |
| 질문 버전 | `v1.1` |

### 이유
AI 모델은 수시로 업데이트된다. 3개월 후 같은 질문을 다시 재도 결과가 다를 수 있다.
그 차이가 "개선의 성과"인지 "모델 업데이트의 영향"인지 구분하려면 모델을 기록해야 한다.

## 7. 측정 불확실성과 결과 해석 기준

### AI 응답의 비결정론적 특성
동일 질문을 같은 날 여러 번 실행하면 결과가 다를 수 있다.
현재 측정 방식은 **1회 측정**이다 — 확률적 노출 여부를 단정하지 않는다.

### 결과 해석 원칙
| 표현 | 허용 | 이유 |
|---|---|---|
| "이 질문에서 언급됨" | ✅ | 측정된 사실 |
| "AI가 항상 추천함" | ❌ | 1회 측정으로 단정 불가 |
| "노출률이 개선됨" | ✅ (전후 비교 시) | 측정 결과 변화 |
| "매출이 증가할 것" | ❌ | 인과관계 미확인 |
| "경쟁사보다 노출 많음" | ❌ (경쟁사 측정 없이) | 측정하지 않은 주장 |

### FAILED 처리 원칙
- `FAILED`는 "언급되지 않았다"가 아니다.
- 리포트에서 FAILED 문항 수를 명시하고, 분모에서 제외했음을 표기한다.
- FAILED가 전체의 20% 이상이면 측정 신뢰도 경고를 포함한다.

## 8. 측정 기록 보존

| 파일/DB | 보존 내용 | 수정 가능 여부 |
|---|---|---|
| `results-original.json` | 1차 측정 원본 | **수정 금지** |
| `results-retest.json` | 재측정 결과 | **수정 금지** |
| Supabase `AiSearchRunResult` | 통합 최종 결과 | SSOT |
| 리포트 파일 | 분석·해석 | 버전 관리 |

원본 JSON 파일은 삭제하거나 덮어쓰지 않는다.
오류 수정은 리포트 문서에서 하고, JSON은 사실 그대로 보존한다.
