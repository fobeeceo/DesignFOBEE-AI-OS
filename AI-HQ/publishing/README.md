# AI 출판부 (Publishing Department)

《유리 벽돌을 쌓다》를 비롯한 자서전 원고의 편집·검수·출판 준비를 담당한다.
대표 지시(2026-11-28)로 신설. AI-HQ 조직(CLAUDE.md §4)의 한 부서다.

---

## ⚠️ 가장 먼저 읽을 것 — 원고를 이 저장소에 넣지 않는다

**이 저장소는 PUBLIC이다.** 2026-11-28 GitHub API로 직접 확인했다(`"private": false`).

자서전 원고에는 가족·신앙·실패·금액·실명이 들어간다. `AI-HQ/publishing/00_ORIGINAL/`에
원고를 커밋하면 **그 순간 전 세계에 공개된다.** 되돌릴 수 없다 — Git 이력에 영구히 남고,
이미 복제된 사본은 회수할 수 없다.

그래서 작업 폴더는 `.gitignore`로 통째로 제외했다(`docs/`와 같은 방식, DOCUMENT-POLICY.md §2).
이 README와 코드만 추적한다.

**원고는 어디에 두는가**
- 원본·작업본: 대표 PC 또는 Google Drive (SSOT는 Drive, CLAUDE.md §3)
- 이 저장소에는 **원고를 다루는 코드만** 둔다

## 작업 폴더 구조 (로컬·Drive 전용, Git 추적 안 함)

```
AI-HQ/publishing/
├── 00_ORIGINAL/      원본 원고 — 절대 수정하지 않는다
├── 01_WORKING/       작업본 (00에서 복사)
├── 02_EDITING/       교정·교열 결과 (원문·수정안·사유 3단)
├── 03_CONSISTENCY/   정합성 점검표
├── 04_COPYRIGHT/     인용·실명·사진 위험 목록
├── 05_DESIGN/        표지·내지 자료
├── 06_MARKETING/     홍보 콘텐츠
├── 07_QA/            통합 검수
└── 08_APPROVAL/      대표 승인 완료본
```

폴더는 `npm run publishing -- init`으로 만든다.

## AI 직원 구성과 실제 능력

제안받은 7명 중 **이름과 범위를 고친 것이 하나 있다.** 아래가 실제로 할 수 있는 일이다.

| # | 직원 | 할 수 있는 일 | 할 수 없는 일 |
|---|---|---|---|
| ① | **편집장** | 장 구성·목차 초안, 중복 일화 탐지, 서사 흐름 지적 | 어느 구성이 옳은지 결정 — 저자의 몫 |
| ② | **교정·교열** | 맞춤법·띄어쓰기·문장 호흡·반복 표현. 원문·수정안·사유 3단으로 제시 | 문체 최종 승인 |
| ③ | **정합성 점검** ⚠️ | 원고 **안에서** 어긋나는 서술(A장 2000년 ↔ B장 2001년), 근거 없이 단정한 문장, 외부에서 확인 가능한 인용(성경 구절·공개 사건 날짜) 대조 | **대표의 개인사가 사실인지 검증** — 외부 출처가 없다 |
| ④ | **저작권·법률 위험 점검** | 인용문·실명·사진·거래 관련 민감 표현을 목록으로 추출 | 법률 판단 — 변호사의 몫 |
| ⑤ | **출판디자인** | 신국판 편집안, 장 제목, 표지 문구 시안 | 최종 조판 — 디자이너의 몫 |
| ⑥ | **출판마케팅** | 책 소개·저자 소개·보도자료 초안 | 최종 게시 승인 |
| ⑦ | **품질관리** | 각 결과 통합, 미해결 항목 집계, 진행률 보고 | 최종 승인 |

### ③의 이름을 왜 바꿨는가

제안서는 "AI 사실검증 직원 — 연도, 날짜, 금액, 인물, 사업 이력을 확인한다"고 했다.
**AI는 그것을 확인할 수 없다.** "카드론 1,000만 원으로 시작했다"가 사실인지 알 방법이
세상에 없다. 대표만 안다.

이름을 "사실검증"으로 두면 AI가 확인하지 않은 것을 확인했다고 보고하게 된다
(§0-2 원칙 7 위반). 할 수 있는 일로 범위를 줄이고 이름을 바꿨다.
**사실 확인은 대표가 한다.** AI는 "여기가 서로 안 맞습니다", "이 문장은 근거가 없습니다"
라고 짚어줄 뿐이다.

## 절대 규칙

1. **AI는 저자의 경험을 바꾸지 않는다.** 없는 사실·숫자·이름·감정을 만들어 넣지 않는다(§14-A ②).
2. **모든 수정은 원문과 사유가 함께 남는다.** 조용히 고쳐 쓰지 않는다. 고를지는 대표가 정한다.
3. **원본(`00_ORIGINAL/`)은 수정하지 않는다.** 작업은 사본에서 한다.
4. **원고를 저장소에 커밋하지 않는다.**

## 단계별 구축

| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | 원고 분해 + 편집장 + 교정 | **구축됨** |
| 2 | 정합성 점검 + 저작권 위험 점검 | 미착수 |
| 3 | 품질관리 통합 | 미착수 |
| 4 | 디자인·마케팅 | 미착수 |
| 5 | 대표 승인 → 출판사 전달 | 미착수 |

한 번에 7명을 만들지 않는다. 1단계를 실제 원고로 돌려보고 쓸 만한지 확인한 뒤 다음으로 간다.

## 쓰는 법

```bash
npm run publishing -- init                      # 작업 폴더 만들기
npm run publishing -- split  <원고파일>          # 장 단위로 분해
npm run publishing -- editor <원고파일>          # 편집장 — 구성·중복·흐름
npm run publishing -- proof  <원고파일> [장번호]  # 교정 — 원문·수정안·사유
```

`GEMINI_API_KEY`가 필요하다(`split`은 예외 — AI 없이 동작한다).
